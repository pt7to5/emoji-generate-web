# BeEmoji Bad Case 质量链路实施计划

## 阶段 1：可观测与配置边界

1. 为分割与生成模型增加显式配置，默认值保持可回退。
2. 在主体响应中加入 Mask 版本与分割来源。
3. 记录智能修正模式、模型、耗时与失败原因。
4. 增加配置和响应结构测试。

## 阶段 2：智能增选与智能排除

1. 扩展本地分割适配层，支持正向点、负向点和当前 Mask 提示。
2. 增加可替换的远程 SAM 2 Provider；未配置时使用本地兼容实现。
3. 将 Mask edit API 从像素增删改为语义重分割；保留独立精细画笔接口。
4. 前端将 Refine 改为“要这个／不要这个”，并显示重新识别状态。
5. 覆盖正负提示、Mask 版本和回退行为测试。

## 阶段 3：完整视觉单位识别

1. 将视觉检测输出升级为结构化完整视觉单位描述。
2. 按食物、饮品、花朵、动物、玩偶和静物应用默认组合规则。
3. 由结构化框驱动分割，不直接把多个模型的平面框并列返回。
4. 增加解析、去重、异常响应和类别规则测试。

## 阶段 4：生成 Provider 与质量门控

1. 抽象生成 Provider，支持 `qwen-image-3.0-pro` 与 `wan2.7-image-pro` 配置切换。
2. 更新风格提示为“真实主体轻度 Emoji 化”，并预留类别参考图。
3. 一次生成多个候选，增加轮廓、占比、颜色、透明边缘和孤立区域检查。
4. 增加视觉语义复核接口与明确拒绝原因。
5. 只对通过质量门控的候选开放合成。

## 阶段 5：三阶段前端与异步任务

1. 将编辑器整理为选择主体、调整范围、生成确认三个阶段。
2. 生成结果先预览，用户确认后再加入合成列表。
3. 将长时间生成改为任务创建和状态查询。
4. 保留多主体连续替换、撤回和下载。

## 阶段 6：回归与灰度

1. 建立按主体类型分类的固定回归清单。
2. 记录首次识别通过率、修正轮数、生成通过率、P50/P95 耗时和单次成功成本。
3. 在功能开关下进行线上小流量验证。
4. 达到设计文档门槛后再替换旧链路。

## 本地交付边界

代码可以完成 Provider 接口、回退实现、前后端交互、质量门控和自动化测试。以下事项必须在云端配置后才能完成真实效果验收：SAM 2 GPU 服务地址、百炼目标模型权限、类别风格参考图以及足够数量的原始回归图片。
