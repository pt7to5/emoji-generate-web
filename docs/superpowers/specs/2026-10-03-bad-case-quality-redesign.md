# BeEmoji Bad Case 质量链路重构设计

更新时间：2026-10-03  
状态：待用户审核

## 1. 背景与目标

当前测试中的 bad case 不是单点模型偶发失败，而是主体定义、分割、交互修正、风格生成和质量检查连续放大误差：

- 自动识别无法稳定判断“完整视觉组合”，容易混淆核心物品、容器、餐具和附近物体。
- Refine 只是按画笔像素增删 Mask，没有根据用户意图重新识别主体。
- Paint 主要依赖 MobileSAM 正向提示与启发式后处理，复杂摆盘、透明物体和相邻主体容易粘连或缺失。
- 风格化使用 `wan2.6-image` 生成主体，约束中同时混有 Emoji、贴纸、摄影光影等目标，结构控制不足。
- 生成质量检查仅覆盖宽高比和平均颜色，无法拦截类别改变、部件缺失、装饰变化和视角漂移。

本次重构目标：让用户以较少操作选中期望主体，并生成保留原主体身份、结构、颜色、视角和现场光影的轻度 Emoji 化结果。

本期覆盖食物、饮品、花朵、动物、玩偶和常见静物。人物不进入本期范围。

## 2. 产品定义

### 2.1 默认主体

自动识别只返回每个目标的最佳完整视觉单位，不同时展示更小层级候选：

- 食物：完整摆盘，如蛋糕、盘子及明显关联餐具。
- 饮品：杯子、杯内饮品及固定装饰，如吸管、柠檬片。
- 花朵：一束花或一盆花，包括枝叶和容器。
- 动物：单只完整动物及其固定穿戴，不包含主人、笼子和附近玩具。
- 玩偶：完整玩偶及固定装饰。
- 普通静物：单个完整物体。

用户若需要更小范围，通过智能排除删除盘子、花盆等部分；系统不预先展示“完整组合”和“核心物体”两个候选。

### 2.2 目标风格

目标不是传统高饱和卡通贴纸，而是“真实主体轻度 Emoji 化”：

- 保留主体类别、完整外轮廓、视角、比例、组成部件、装饰和颜色布局。
- 保留真实材质、现场光线、色温和阴影关系。
- 仅降低细碎纹理噪声，适度圆润边缘，增加克制、柔和的立体感。
- 禁止擅自增加五官、肢体、装饰、文字或改变主体类别。

现有参考图只覆盖甜品和饮品。花朵、动物、玩偶和静物的风格阈值需在用户补充参考图后校准。

## 3. 用户流程

现有五个并列技术操作收敛为三阶段流程。

### 3.1 选择主体

图片上传后自动识别完整视觉单位，并在画面与缩略图中展示。用户点击高亮区域或缩略图选择主体。

自动识别失败时，直接进入智能涂抹状态，引导用户在目标内部画一笔，不只显示笼统失败信息。

### 3.2 调整范围

Paint 和 Refine 合并为统一的范围调整界面：

- “要这个”：用户在漏选部分涂抹，轨迹作为正向提示。
- “不要这个”：用户在多选部分涂抹，轨迹作为负向提示。
- 服务端基于原图、当前 Mask、正负提示重新分割完整主体，不直接对 Mask 做画笔像素加减。
- 支持逐步撤回提示和 Mask 版本。
- 智能修正连续两次仍不理想时，提供精细画笔作为像素级兜底。

### 3.3 生成与确认

用户确认 Mask 后发起生成。生成结果先单独预览，用户确认后才写回原图。用户可以重新生成或返回调整范围；未确认结果不会污染当前合成图。

## 4. 技术架构

链路拆成四个边界清晰的服务阶段。

### 4.1 场景理解

视觉理解模型读取原图，输出结构化主体描述：

- 目标类别和名称。
- 完整视觉单位的检测框。
- 核心主体、组成部分、固定附属物和无关邻近物。
- 建议的正向种子点、负向种子点及置信度。

场景理解只负责语义和分组，不直接生成最终 Mask。输出通过稳定的内部数据结构与具体模型供应商解耦。

### 4.2 交互式分割

使用 SAM 2 作为主分割模型：

- 初次分割接收检测框及语义种子点。
- 智能修正接收当前 Mask、累积正向点和累积负向点。
- 每轮返回多个候选 Mask、模型质量分和稳定性指标。
- 业务层结合提示覆盖率、边界稳定性、面积突变、连通区域和场景语义选择最佳候选。

SAM 2 推理从当前 2 vCPU / 4 GB 的 FC 容器拆出，部署到独立 GPU 推理服务。FC 保留鉴权、任务编排、文件管理、图像后处理和第三方 API 调用。

精细画笔继续使用现有像素增删逻辑，但只作为明确选择的兜底模式。

### 4.3 受控风格生成

风格生成建立统一 Provider 接口，第一轮比较：

- `qwen-image-3.0-pro`
- `wan2.7-image-pro`

每次请求至少包含：

- 透明或中性背景上的完整主体图。
- 原图中的局部环境上下文。
- 类别对应的目标风格参考图。
- 结构与颜色约束描述。

同一次生成获取多个候选。模型选择通过固定回归集完成，不根据单张演示结果决定。表现较好的模型作为主通道，另一模型作为受控回退通道。现有 `wan2.7-image` 背景修复可以继续保留，与主体风格生成职责分离。

### 4.4 质量门控

所有生成结果必须通过质量门控后才可展示为可合成结果。

程序检查：

- 输出可解码且透明主体非空。
- 主体未被裁切，轮廓比例和占比无异常突变。
- 主色、辅色、亮度和饱和度偏差在阈值内。
- 不存在异常大孔洞、多余孤立区域和明显白边。

视觉语义检查：

- 主体类别一致。
- 组成部件、数量和关键装饰未丢失或新增。
- 视角、姿态和方向一致。
- 风格符合对应类别参考图。
- 无新增文字、五官、肢体和无关物体。

候选按综合分排序。全部失败时最多进行一次带有具体失败原因的纠偏重试；仍失败则返回“主体一致性不足”等可定位错误，不进入合成。

## 5. 数据与接口

主体对象新增以下内部状态：

- `groupDescription`：完整视觉单位描述。
- `parts`：核心主体、组成部分和附属物。
- `maskVersion`：当前 Mask 版本。
- `positivePrompts`、`negativePrompts`：累积用户提示。
- `segmentationModel`、`segmentationScore`：分割来源及质量。
- `generationModel`、`generationSeed`：生成来源及复现信息。
- `qualityScores`、`rejectionReasons`：质量评分和拒绝原因。

前端不直接依赖具体模型名，只消费候选主体、Mask 版本、任务阶段、预览结果和错误码。

生成链路改为异步任务：创建任务、查询阶段、返回候选预览、用户确认合成。阶段至少包括主体准备、风格生成、质量检查和可预览。

## 6. 错误处理与可观测性

每次任务记录：

- 图片、主体、Mask 和提示版本。
- 各模型名称、版本、参数、耗时和供应商请求 ID。
- 每个候选的质量分、拒绝原因和最终用户选择。
- 自动识别、智能修正、生成、背景修复和合成的分阶段耗时。

错误码按阶段区分：场景理解失败、分割无有效候选、智能修正冲突、生成失败、质量门控拒绝、背景修复失败和合成失败。前端提供对应的下一步动作。

任务图片继续写入 OSS，并遵守后续确定的生命周期规则。日志不写入 API Key 和不必要的原始图片内容。

## 7. 验收与评测

建立固定回归集，至少按食物、饮品、花朵、动物、玩偶和普通静物分类。当前样本先进入回归集，用户后续补充的原图、结果和风格参考持续加入。

每个样本记录：

- 自动识别是否选中合理完整视觉单位。
- 智能修正是否能在一至两次提示内达到期望范围。
- Mask 是否存在粘连、缺边、孔洞和透明边缘问题。
- 生成主体的类别、结构、部件、装饰、颜色、视角和风格是否合格。
- 各阶段耗时、调用成本和失败原因。

首版上线门槛：

- 自动识别明显优于当前线上版本，完整组合误选可通过一次智能排除修正。
- 常见漏选和多选能够在一至两轮智能修正内解决。
- 任何未通过身份与结构检查的生成结果都不会进入合成。
- 多主体连续替换、撤回和下载功能不回退。
- 桌面与手机端完成同一套回归流程。

在样本数量足以形成统计意义前，不承诺虚假的固定准确率；先记录通过率、人工修正次数、P50/P95 耗时和单次成功成本，再确定正式 SLA。

## 8. 实施与发布顺序

1. 增加任务记录、模型版本、分阶段日志和回归数据结构。
2. 建立场景理解的结构化输出与完整视觉单位规则。
3. 接入 SAM 2 GPU 推理服务，实现正负提示和 Mask 迭代。
4. 将前端重构为选择、智能调整、生成确认三阶段。
5. 建立生成 Provider 接口并对比 `qwen-image-3.0-pro` 与 `wan2.7-image-pro`。
6. 实现程序检查、视觉语义检查、候选排序和一次纠偏重试。
7. 接入异步生成任务和用户确认后合成。
8. 使用功能开关进行线上小流量验证，达到回归门槛后替换旧链路。

每一步均保留旧链路回退能力。不得在没有质量记录和固定回归结果的情况下直接全量切换。

## 9. 非目标

- 本期不处理人物与多人场景。
- 本期不训练自有基础生成模型。
- 本期不为每类主体预先展示多层级候选。
- 本期不以更多提示词堆叠代替分割、结构控制和质量门控。
- 本期不把自动生成结果未经确认直接写回用户图片。
